# 讨饭

麦麦（MaiBot）插件。群友提到打钱、请客、投喂时，让机器人伸手要一张收款码；顺带把收到的打赏记进本地账本，记账要管理员点头才算数。

## 功能

| 功能 | 触发方式 |
| --- | --- |
| 讨饭 | `beg_for_money` 工具 / `/讨饭` 命令，发一条只含收款码的合并转发 |
| 道谢 | 讨饭后开一个窗口，窗口内有人说「打了」「转了」，或管理员手动 `/已打钱`，让 Planner 生成一句感谢 |
| 记账 | `record_payment` 工具 / `/打赏 15` 命令。群友触发时不直接落账，先私聊管理员确认 |
| 查账 | `check_ledger` 工具 / `/收款` 命令，支持今天、昨天、全部、最近 N 天、指定日期 |

工具是给 LLM 主动调用的，命令是给人敲的，两者共用同一套底层逻辑。

## 安装

1. 把仓库内容放进 `MaiBot/plugins/maibot-beg-for-money/`，目录里必须有 `_manifest.json` 和 `plugin.py`
2. 在 WebUI 插件页启用，或重启麦麦
3. 首次加载会自动生成 `config.toml`

要求：MaiBot 1.3.x + maibot-plugin-sdk 2.16.x。SDK 下限写的是 2.16.0，因为插件用到的 `maibot_sdk.types`、`PluginConfigBase` 和 `ctx.maisaka.proactive` 这一组能力要到 2.16 才齐，更早的版本会直接 ImportError。

## 配置

至少配这两项，否则讨饭不可用：

| 字段 | 说明 |
| --- | --- |
| `[beg] qr_image_path` | 收款码图片的**绝对路径**，留空则工具直接返回失败 |
| `[beg] admin_ids` | 管理员 QQ 号数组，记账确认、`/讨饭`、`/已打钱` 都认这个名单 |

其余常用项：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `beg.enabled` | `true` | 关掉后工具仍注册，但调用直接失败 |
| `beg.sender_name` | `麦麦` | 合并转发节点上显示的昵称 |
| `beg.cooldown_seconds` | `600` | 同一聊天流两次讨饭的最小间隔 |
| `beg.daily_limit` | `3` | 每个聊天流每天最多讨几次，`0` 表示不限 |
| `beg.thanks_window_seconds` | `600` | 讨饭后多久内算「可能有人打钱」的窗口 |
| `beg.thank_intent` | 见配置 | 触发道谢时交给 Planner 的意图 |
| `beg.admin_only` | `false` | 开启后手动命令只给 `admin_ids` 用。**也管 `/收款` 和 `check_ledger`**，见下方隐私说明 |
| `ledger.enabled` | `true` | 记账总开关 |
| `ledger.currency` | `元` | 金额单位 |
| `ledger.recent_days` | `7` | `/收款` 默认展示最近几天 |
| `ledger.require_approval` | `true` | 群友触发的记账要管理员私聊确认 |
| `ledger.approval_timeout_seconds` | `1800` | 待确认记录的有效期 |

## 命令

| 命令 | 谁能用 | 说明 |
| --- | --- | --- |
| `/讨饭` `/要饭` | 所有人（或 `admin_only` 开启后仅管理员） | 发收款码 |
| `/已打钱` `/打了` | 同上 | 手动触发道谢 |
| `/打赏 15 [备注]` | 所有人 | 记账；非管理员触发会转成待确认 |
| `/收款 [范围]` | 同上 | 查账 |
| `/待确认` | 管理员 | 列出待确认的记账 |
| `/确认 [编号]` | 管理员，**仅私聊** | 确认记账并在原群道谢 |
| `/不记 [编号]` | 管理员，**仅私聊** | 丢弃这笔 |

`/收款` 的范围写法：留空（今天 + 最近 N 天 + 累计）、`今天`、`昨天`、`全部`、`7`（最近 7 天）、`2026-10-27`、`10-27`。

## 记账审批流程

```
群友说「我转了 15」
   ↓ LLM 调 record_payment
不直接记账 → 生成待确认 #1 → 私聊所有管理员
   ↓
群里回「收到 15.00元 的说法，已经报给管理员了，等他点头才算数（编号 1）」
   ↓ 管理员私聊回 /确认 1
写进账本 → 在原群触发送谢
```

管理员自己触发的记账不走这道手续，直接生效。待确认记录落盘在 `data/plugins/github.lbcheng1145.beg-for-money/approvals.json`，插件重载或重启都不会丢。

## 常见问题

**别人能看到我收了多少吗？**
`beg.admin_only` 默认是 `false`，意味着任何群友都能用 `/收款`，也能让模型调 `check_ledger` 查到收入汇总。不想公开营收就把它改成 `true`，此时 `/收款`、`/待确认`、`/确认`、`/不记` 都只认 `admin_ids` 里的人。

⚠ 开启后模型调 `check_ledger` 也会被一律拒绝：工具调用拿不到能信任的调用者身份（模型有机会自己塞 `user_id`），插件按「认不出是谁」处理，宁可拒绝也不放行。想查收入就直接发 `/收款` 命令。

**为什么记账不直接生效？**
个人收款码没有到账回调，谁都能顺口说一句「我转了」。直接落账等于让任何人往账本里写数字，而账本是纯手工维护的，记错了只能改文件。所以群友触发的记账先挂成待确认。

**为什么用 `/不记` 而不是 `/拒绝`？**
QQ 会把「拒绝」这个词转成表情，管理员收到的命令就成了一个图标，没法照做。

**收款码发不出去？**
检查 `qr_image_path` 是不是绝对路径、文件是否真实存在。插件目录里的 `assets/` 只是放图的位置，图片本身不会随插件分发。

**手动改了账本文件为什么不生效？**
账本在内存里有一份缓存，每次记账会把整份列表写回文件。手动改完必须重载插件，否则内存里的旧数据会把你的修改覆盖掉。

**能自动识别到账吗？**
不能。试过监听 Windows 通知中心和截图 OCR，微信 4.x 既不往通知中心推，最小化窗口也抓不到内容。个人收款码本身也没有回调，所以只能「手动记账 + 口头确认」。

## 数据文件

都在 `data/plugins/github.lbcheng1145.beg-for-money/` 下：

- `ledger.json` — 账本
- `approvals.json` — 待确认的记账
